# WeChat Channel Integration Guide

PilotDeck connects to WeChat through the **WeChat iLink Bot API** (Tencent's official personal-account bot interface). This document covers the full process from scratch deployment to normal operation, including common pitfalls.

---

## Prerequisites

| Requirement | Details |
|-------------|---------|
| **Node.js ≥ 18** | Native `fetch` support required |
| **WeChat ClawBot Beta Access** | Your WeChat account must be in the iLink Bot beta allowlist |
| **WeChat Client Version** | iOS ≥ 8.0.53 / Android ≥ 8.0.53 / macOS ≥ 3.8.9 |
| **Network** | Server must reach `https://szextshort.weixin.qq.com` (iLink API endpoint) |
| **LLM API Key** | A valid key for OpenRouter / Anthropic / self-hosted provider |

:::warning Important
If your WeChat account is **not** on the ClawBot beta allowlist, scanning the QR code will return `errcode: -14 session timeout`. This is not a code issue — you need to apply for access through Tencent/OpenClaw.
:::

## Architecture Overview

```
WeChat User
   │
   │ (WeChat iLink Bot API / HTTPS long-poll)
   ▼
┌────────────────────┐
│  WeixinChannel     │ ← ChannelAdapter implementation
│  (long-poll loop)  │
└────────┬───────────┘
         │ gateway.submitTurn()
         ▼
┌────────────────────┐
│  PilotDeck Gateway │ ← routes to LLM provider
└────────┬───────────┘
         │ AsyncIterable<GatewayEvent>
         ▼
┌────────────────────┐
│  LLM (DeepSeek /   │
│  Claude / GPT)     │
└────────────────────┘
```

Flow:
1. `WeixinChannel.start()` → checks local credentials → triggers QR login if none found
2. After login, enters `pollLoop()` which long-polls new messages via `ILinkClient.poll()`
3. Receives user message → `gateway.submitTurn()` submits to LLM
4. Streams `GatewayEvent` → `renderWeixinEvent()` assembles reply text
5. Sends reply back to WeChat via `client.sendTextChunked()` (each chunk ≤ 2000 characters)

## Configure LLM Provider

Edit `~/.pilotdeck/pilotdeck.yaml`:

```yaml
schemaVersion: 1
agent:
  model: openrouter/deepseek/deepseek-v4-flash  # or anthropic/claude-sonnet-4.6

model:
  providers:
    openrouter:
      protocol: openai
      url: https://openrouter.ai/api/v1
      apiKey: sk-or-v1-xxxxxxxxxxxxxxxx  # your OpenRouter API key
      models:
        deepseek/deepseek-v4-flash:
          capabilities:
            maxOutputTokens: 32768
```

:::tip
When OpenRouter free credits run out you will get `Insufficient credits`. Top up at https://openrouter.ai/settings/credits.
:::

## Start & QR Login

```bash
# Start PilotDeck server (default port 18789)
cd /path/to/PilotDeck
node dist/cli/pilotdeck.js server
```

On first startup the terminal displays:

```
╔══════════════════════════════════════════════╗
║  WeChat iLink Login — Scan QR with WeChat   ║
╚══════════════════════════════════════════════╝

[weixin] QR login URL:
https://szextshort.weixin.qq.com/mmcgiqrcode/...
[weixin] Waiting for scan...
```

Steps:
1. Copy the link from the terminal and open it in a browser (displays a QR image)
2. Scan with the **WeChat account that has beta access**
3. Confirm login on your phone
4. Terminal shows `[weixin] Login successful! accountId: xxx`

Credentials are saved automatically — subsequent starts skip the QR flow.

## Messaging

| Action | Method | Notes |
|--------|--------|-------|
| Normal chat | Send text directly | Continues in the current session |
| New session | Send `/new` | Creates a brand-new session; subsequent messages go there |
| New + first message | Send `/new hello` | Creates a new session with "hello" as the first message |

- Each WeChat user (`from_user_id`) has an independent session
- Session key format: `weixin:chat={userId}:general` or `weixin:chat={userId}:s_{uuid}`
- Messages from the same user are processed sequentially (no concurrent responses)

## Credential Management

Credential file: `~/.pilotdeck/weixin-credentials.json`

```json
{
  "baseUrl": "https://szextshort.weixin.qq.com",
  "botToken": "xxxxxxxx",
  "accountId": "wxid_xxxxxxxx",
  "cursor": "..."
}
```

| Field | Description |
|-------|-------------|
| `baseUrl` | iLink API endpoint |
| `botToken` | Bot token obtained after login |
| `accountId` | The wxid of the logged-in WeChat account |
| `cursor` | Long-poll cursor (for resuming without duplicates) |

**Operations:**

```bash
# View current credentials
cat ~/.pilotdeck/weixin-credentials.json

# Force re-login (delete credentials then restart)
rm ~/.pilotdeck/weixin-credentials.json
# Then restart the PilotDeck server
```

## Proxy Configuration

PilotDeck supports a global HTTP proxy via environment variables (affects all `fetch()` calls):

```bash
# Priority: PILOTDECK_PROXY > https_proxy > HTTPS_PROXY > http_proxy > HTTP_PROXY
export PILOTDECK_PROXY=http://127.0.0.1:7890
```

:::caution Note
If a proxy is configured but the proxy server is not running, `fetch` will fail immediately. The iLink API does not need a proxy (direct connection within China) — only overseas LLM API calls require one.

**Solution:** If you only need to proxy LLM requests, **do not set global proxy environment variables**. The current implementation only loads `undici` when the env var exists; without it, native `fetch` works unaffected.
:::

## Troubleshooting

### 1. `errcode: -14 session timeout`

**Cause:** WeChat account is not on the ClawBot beta allowlist, or the session has expired.

**Fix:**
- Confirm your account has been approved for beta access
- Confirm the WeChat client version meets minimum requirements
- Delete credentials and re-scan: `rm ~/.pilotdeck/weixin-credentials.json`

### 2. `fetch failed` / Network Error

**Cause:** A global proxy is interfering with iLink long-poll requests.

**Fix:**
- Verify `PILOTDECK_PROXY`, `HTTPS_PROXY`, etc. are unset (or point to a running proxy)
- If no proxy is needed: `unset PILOTDECK_PROXY HTTPS_PROXY HTTP_PROXY`

### 3. `Insufficient credits` (OpenRouter)

**Cause:** OpenRouter account balance is depleted.

**Fix:**
- Top up at https://openrouter.ai/settings/credits
- Or switch to another provider (e.g. self-hosted edgeclaw)

### 4. `invalid x-api-key`

**Cause:** The API key in `~/.pilotdeck/pilotdeck.yaml` is invalid or a placeholder.

**Fix:**
- Verify the `apiKey` field contains a real key
- Do not leave `PLACEHOLDER_RUN_ONBOARDING_TO_REPLACE`

### 5. QR Code Expired

**Cause:** The QR login link is valid for approximately 3–5 minutes.

**Fix:**
- The SDK automatically refreshes the QR code (terminal shows "QR expired, refreshing...")
- If it keeps failing, restart the server to re-trigger login

### 6. Messages Received but Cannot Reply / `no context_token`

**Cause:** Each incoming user message carries a `context_token` required for replying. If the first message lost its token, replies fail.

**Fix:**
- This rarely happens unless poll was interrupted and historical messages lack tokens
- Ask the user to send another message to recover

### 7. Reply Truncated

**Cause:** WeChat has a per-message character limit (~2048 characters).

**Fix:**
- `WeixinChannel` includes `sendTextChunked()` which automatically splits at 2000 characters
- Very long LLM responses are sent as multiple messages in sequence

### 8. Old Messages After Restart

**Cause:** The `cursor` was not saved correctly.

**Fix:**
- Graceful shutdown (Ctrl+C) automatically saves the cursor
- After a crash, the next start may receive messages from after the interruption (usually harmless)

## File Structure Reference

```
PilotDeck/
├── src/adapters/channel/weixin/
│   ├── WeixinChannel.ts        # Main logic: login, poll, dispatch, reply
│   ├── WeixinSessionMapper.ts  # Session management (/new command, key mapping)
│   └── weixin-render.ts        # GatewayEvent → WeChat reply text
├── src/cli/
│   ├── pilotdeck.ts            # CLI entry, instantiates WeixinChannel
│   ├── pilotdeckServer.ts      # Starts server, calls weixin.start()
│   └── proxy.ts                # Global proxy install (loads undici only when env set)
├── tests/adapters/
│   └── channel-weixin.test.ts  # Unit tests
└── ~/.pilotdeck/
    ├── pilotdeck.yaml              # Main config (provider keys)
    └── weixin-credentials.json     # WeChat login credentials (auto-generated)
```
